# DSH-Opencode2API-hbk 实施计划

> 状态：v7（2026-11-12，人工裁决：**API 入口静默保留 + 阶段 3 缩减为轻量收尾**；阶段 0/1 已验收，P2 已关闭，0.2.4 实测否决已回退 0.2.3）。  
> 目标：开发一个 **DSH 框架插件**（交付形态），全程 **TypeScript**，把本地真实 opencode CLI 接入 DSH，并额外提供**对外转发 API**（2026-11-12 起静默保留，见 §0 要点 3 注）。  

## 0. 人工确认的四个要点（最高优先级约束）

1. **交付形态 = DSH 插件**：`dsh plugin add` 可安装，跑在 DSH 进程内；不是独立软件/脚本。
2. **实现语言 = 全程 TypeScript/JavaScript**：与 DSH 生态一致；不写 Go sidecar、不引原生模块。唯一子进程是官方 opencode CLI 本体（用户已安装）。
3. **双入口**：默认向 DSH 提供通道（LlmAdapter，模型出现在选择器）；**另外提供 HTTP 转发 API** 供外部程序调用，允许本机或网络访问。
   > **2026-11-12 人工裁决：API 入口静默保留。** 后端已实现并实测通过（h4：模型列表/流式+非流式问答/401 鉴权），但实测几乎无使用必要 ⇒ 保持现状、留而不用：默认关闭、不做设置界面、不再投入。已知缺口（tools 参数忽略、流式无 usage、模型名不校验、请求体无大小上限）一并冻结。**将来启用 API 或分发他人前，须补安全审计与双入口并发压测。**
4. **不伪装**：不自造上游请求、不模仿请求头；直接复用本地真实 CLI 及其用户凭据/认证。对 opencode 服务器而言，就是官方 CLI 在正常使用和交互。

> 贯穿原则（人工裁决）：**稳定是最高优先级**——额外上下文开销、内存占用均为可接受代价；一切取舍以稳定为先，不做聪明但脆的优化。

## 1. 背景与问题定论

- 旧插件（opencode2dsh）走"伪装 CLI 的匿名免费通道"，上游风控已升级为**认凭据**：无凭据一律 403 FreeTierError；匿名通道按 IP 限流，持续 429。
- 本机 CLI（opencode v2.2.5，已登录）一直正常 → 账号与凭据没问题，死的是"伪装"路线。
- 结论（参考项目 issue #76 的 A/B 证据支持）：**放弃自造上游 HTTP 客户端，改为驱动本地真实 opencode**。上游看到的即真 CLI 流量；上游改风控由官方 CLI 先适配。

## 2. 总体架构（双入口、单核心）

```
入口A：DSH 聊天界面 ── LlmAdapter（模型列表 + 流式 chunk）──┐
                                                          ▼
                                        插件核心（TS，DSH 进程内）
                                        会话管理 + 协议翻译 + 进程看护
                                                          ▲
入口B：外部程序 ── HTTP 转发 API（OpenAI 兼容，本机/网络）─┘
                                                          │
                                        本机 opencode serve 子进程
                                        （v2.2.6 官方二进制 + 本机现有登录凭据）
                                                          ▼
                                                  OpenCode 上游
```

- 两个入口共用同一条内部通道；每个 DSH 会话 / 外部 API 调用映射到独立的 opencode 会话，互不串话。
- 对外 API 默认只听 `127.0.0.1`；开放网络须显式配置监听地址 + 访问 token（网络曝光 = 账号曝光，这道闸默认关着）。

### 必须改造（与参考实现的差异）

1. **v1 → v2 适配**：参考实现面向老版（Go 运行时、auth.json）；本机 v2.2.6 为 TS/Bun 重写、SQLite 存储（`~/.local/share/opencode/opencode.db`）。serve API 形状、凭据机制、健康端点全部以 `opencode-dev` 源码 + 实测为准。Go 内存招数（GOMEMLIMIT/GOGC）不适用。
2. **砍匿名车道**：删除匿名直连、姊妹主机重试、IP 池、三级目录回退链。本地 CLI 即唯一通道。
3. **凭据直接复用，不抄快照**：直接复用本机 CLI 现有登录状态（SQLite credential 表 + 默认数据目录），CLI 侧刷新/重登录自动生效。插件不做"凭据保管人"，无第二份凭据落地。
4. **模型目录简化**：直接取自本地 opencode 的 providers/models 接口。免费判定**首选 serve 模型成本元数据（cost 全 0 → 免费）**，以前置探针确认其可靠性；不可靠则回退 models.dev（见 §4 阶段 2 前置探针）。
5. **补真流式**：订阅 v2 `/event` SSE 做 token 级增量（阶段 2 落地）。
6. **新增 HTTP API 服务层**（参考项目没有的形态）：OpenAI 兼容 `/v1/chat/completions` + `/v1/models`，SSE 流式响应，监听 host/port 可配，token 鉴权（阶段 2 落地）。

## 5. 关键取舍与风险（已裁选，记录理由）

| 决策 | 选择 | 理由 / 替代方案 |
| --- | --- | --- |
| 上游通道 | 本地 serve 委托唯一通道 | 伪装路线已被凭据门禁封死（A/B 证据）；替代"直连+真凭据"仍是自造客户端，上游改风控即失效，弃 |
| 对外 API 协议 | OpenAI 兼容（/v1/chat/completions + /v1/models） | 外部工具几乎都认，接入零成本；自定义协议无人能直接对接，弃 |
| 网络暴露 | 默认 127.0.0.1，网络监听显式配置 + token | 网络曝光=账号曝光，闸默认关；替代"默认开放"风险不可控，弃 |
| 凭据 | 直接复用本机 CLI 现有登录，不复制快照 | 人工要点 4；CLI 刷新/重登录自动生效，插件不做凭据保管人 |
| 工具能力 | 阶段 2 补路径 B（opencode 原生工具） | 阶段 0 证 prompt 无 tools 字段；路径 B 复用审批拦截改白名单放行，最稳；DSH 工具透传（client-mcp）复杂且实验性，弃/后续研究 |
| 工具模式安全 | toolMode 默认 off + 白名单 + 每回合上限 | 工具在本机由 opencode 真实执行（能力的必然代价），白名单是风险手闸；默认关保兼容与回退 |

| 账号风险 | 如实告知 | 桥接真凭据若被上游判异常，后果账号自负；流量由真 CLI 发出，形状与正常一致，已是最干净路线 |
